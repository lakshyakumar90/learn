Assigning an object doesn't duplicate it; it hands out another key to the
same locker. Interviewers ask this because shared-reference bugs — state
edited through an "independent" copy — are the most common UI defects there
are.

## Real-life situation

A receipt view aliases the live cart object to format it. Adding a
"free gift" line to the receipt silently rewrites the cart total, and the
customer is charged for the gift. The fix: format a real copy, so the receipt
can never reach back into the cart.

Seen in: React state updates replace objects instead of mutating them, so
change detection sees a new reference (React 16.8, 2019,
[useState reference](https://react.dev/reference/react/useState)).

## When to copy how

Flat data: spread or `slice`. Nested data you edit: spread every edited
level, or `structuredClone` the whole tree. Data with functions or class
instances: copy by hand, because cloners drop behavior.

## Key takeaways

- Primitives copy by value; objects copy by reference.
- Spread is shallow: nested objects stay shared.
- `structuredClone` deep-copies data, but drops functions and prototypes.
