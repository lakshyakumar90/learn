### Build the working version

<CodeRunner title="Build: Higher-order functions" expect="discounted 15\ndiscounted 0\nadjusted 16,12\ncontract true">
{`function withLogging(operation, label) {
  return (...args) => {
    const result = operation(...args);
    console.log(label, result);
    return result;
  };
}
function applyDiscount(total, amount) {
  return Math.max(0, total - amount);
}
const checkoutDiscount = withLogging(applyDiscount, "discounted");
checkoutDiscount(20, 5);
checkoutDiscount(3, 5);
const cart = [4, 8, 6];
const expensive = cart.filter((price) => price >= 6);
const withTax = expensive.map((price) => price * 2);
console.log("adjusted", withTax.join(","));
const contractChecks = [applyDiscount(3, 5) === 0, cart.join(",") === "4,8,6"];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

Preserve arguments, results and receivers when required. Logging remains a side effect even when the wrapped arithmetic is pure.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>
