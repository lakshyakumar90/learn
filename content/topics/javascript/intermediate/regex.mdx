### Build the working version

<CodeRunner title="Build: Regular expressions" expect="Meera_1 true\na false\n&lt;script&gt; false\ntea-shop false\norders 42,73\nno HTML validation with regex\ncontract true">
{`function validateUsername(input) {
  const clean = input.trim();
  if (clean.length < 3 || clean.length > 20) return false;
  return /^[a-z][a-z0-9_]*$/i.test(clean);
}
const submissions = ["Meera_1", "a", "<script>", "tea-shop"];
for (const username of submissions)
  console.log(username, validateUsername(username));
const tagged = "Order #42 and #73";
const orderIds = Array.from(tagged.matchAll(/#(\\d+)/g), (match) => {
  return Number(match[1]);
});
console.log("orders", orderIds.join(","));
console.log("no HTML validation with regex");
const contractChecks = [
  validateUsername("a") === false,
  validateUsername("Meera_1") === true,
];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

## Why it works this way

Avoid ambiguous nested quantifiers on untrusted input. Regex is useful for regular patterns, not arbitrary HTML or full email grammar.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>

## Mistakes that reach production

### Global validation alternates results

Run the reproduction, then the corrected version. Compare the value at the boundary; the fix changes the cause rather than hiding the symptom.

## Takeaways

- Check the value that crosses the boundary before choosing the syntax.
- Anchors constrain the whole string; matchAll yields captured matches.
- Avoid ambiguous nested quantifiers on untrusted input.
