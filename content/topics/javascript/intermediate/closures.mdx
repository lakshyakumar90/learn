## How it works

<ScenarioPlayer scenario="closure-counter" />

Each makeCart call creates a new items binding. Its methods retain and share that binding, while another cart gets independent storage.

### Build the working version

<CodeRunner title="Build: Closures" expect="added\nadded\ncart full\ntotal 12\ngift count 0">
{`function makeCart(limit) {
  const items = [];
  return {
    add(item) {
      if (items.length >= limit) return "cart full";
      items.push({ ...item });
      return "added";
    },
    total() {
      return items.reduce((sum, item) => sum + item.price, 0);
    },
    count() {
      return items.length;
    },
  };
}
const groceries = makeCart(2);
const gifts = makeCart(1);
console.log(groceries.add({ name: "rice", price: 8 }));
console.log(groceries.add({ name: "tea", price: 4 }));
console.log(groceries.add({ name: "coffee", price: 6 }));
console.log("total", groceries.total());
console.log("gift count", gifts.count());`}
</CodeRunner>

## Why it works this way

Private state prevents accidental writes, but long-lived callbacks can retain data. Copy incoming items so callers cannot edit stored prices.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>

- Each makeCart call creates a new items binding.
- Private state prevents accidental writes, but long-lived callbacks can retain data.
