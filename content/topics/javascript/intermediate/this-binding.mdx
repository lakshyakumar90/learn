## How it works

<Diagram id="js-exec-context" />

An ordinary function gets this from its call site. Bind fixes a receiver; an arrow wrapper calls the method through its owner.

### Build the working version

<CodeRunner title="Build: this binding" expect="invoice\nreceipt\nreceipt\nreport\nreport\ncontract true">
{`const toolbar = {
  selected: "draft",
  rename(next) {
    this.selected = next;
    return this.selected;
  },
};
function dispatch(handler, value) {
  return handler(value);
}
const boundRename = toolbar.rename.bind(toolbar);
const arrowRename = (value) => toolbar.rename(value);
console.log(dispatch(boundRename, "invoice"));
console.log(dispatch(arrowRename, "receipt"));
console.log(toolbar.selected);
const secondToolbar = { selected: "notes" };
console.log(toolbar.rename.call(secondToolbar, "report"));
console.log(secondToolbar.selected);
const contractChecks = [
  toolbar.selected === "receipt",
  secondToolbar.selected === "report",
];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

Binding creates a new function identity. Keep it for listener removal, and remember arrows inherit their surrounding this.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>
