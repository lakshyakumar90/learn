### Build the working version

<CodeRunner title="Build: Classes — including private fields and statics" expect="tea\n1\nname catalog\nmethod on prototype true">
{`class SearchPlugin {
  #queries = [];
  constructor(name) {
    this.name = name;
  }
  search(query) {
    const clean = query.trim();
    if (!clean) return [];
    this.#queries.push(clean);
    return [clean];
  }
  count() {
    return this.#queries.length;
  }
}
const search = new SearchPlugin("catalog");
console.log(search.search(" tea ").join(","));
console.log(search.count());
console.log("name", search.name);
console.log(
  "method on prototype",
  Object.hasOwn(SearchPlugin.prototype, "search"),
);`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

Detached methods still lose this. Classes clarify ownership, but factories and composition often handle independent capabilities more simply.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
