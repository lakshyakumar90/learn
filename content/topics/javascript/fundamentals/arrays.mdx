### Build the working version

<CodeRunner title="Build: Arrays and array methods" expect="total 20\nold quantity 2\nnew quantity 3\nseparate arrays true\ncontract true">
{`const cart = [
  { id: "tea", price: 4, quantity: 2 },
  { id: "rice", price: 8, quantity: 1 },
];
function updateQuantity(items, id, quantity) {
  return items.map((item) => {
    return item.id === id ? { ...item, quantity } : item;
  });
}
const updated = updateQuantity(cart, "tea", 3);
const inStock = updated.filter((item) => item.quantity > 0);
const total = inStock.reduce((sum, item) => {
  return sum + item.price * item.quantity;
}, 0);
console.log("total", total);
console.log("old quantity", cart[0].quantity);
console.log("new quantity", updated[0].quantity);
console.log("separate arrays", cart !== updated);
const contractChecks = [cart[0].quantity === 2, updated[0].quantity === 3];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

## Why it works this way

An array copy still shares nested records. Copy changed paths deliberately and reuse unchanged references only while their ownership contract stays safe.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>

## Takeaways

- Check the value that crosses the boundary before choosing the syntax.
- Map returns a new array, filter selects lines and reduce totals them.
- An array copy still shares nested records.
