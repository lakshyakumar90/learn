### Build the working version

<CodeRunner title="Build: Functions" expect="pickup 16\ndelivery 19\nunchanged true\nreuse 19\ncontract true">
{`function calculateTotal(items, shipping = 0) {
  if (!Array.isArray(items)) throw new TypeError("items must be an array");
  const subtotal = items.reduce((sum, item) => {
    return sum + item.price * item.quantity;
  }, 0);
  return subtotal + shipping;
}
const cart = [
  { name: "tea", price: 4, quantity: 2 },
  { name: "rice", price: 8, quantity: 1 },
];
const before = JSON.stringify(cart);
console.log("pickup", calculateTotal(cart));
console.log("delivery", calculateTotal(cart, 3));
console.log("unchanged", JSON.stringify(cart) === before);
const priceForDelivery = (items) => calculateTotal(items, 3);
console.log("reuse", priceForDelivery(cart));
const contractChecks = [
  calculateTotal(cart) === 16,
  JSON.stringify(cart) === before,
];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

Keep network and DOM effects outside pure calculations. Hidden global dependencies make the same inputs produce surprising results.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>
