### Build the working version

<CodeRunner title="Build: Control flow" expect="empty\ninvalid quantity\nout of stock\nready\ncontract true">
{`function decideCheckout(cart, stock) {
  if (cart.length === 0) return "empty";
  for (const item of cart) {
    if (!Number.isInteger(item.quantity) || item.quantity < 1) {
      return "invalid quantity";
    }
    if ((stock[item.name] ?? 0) < item.quantity) return "out of stock";
  }
  return "ready";
}
const stock = { tea: 2, rice: 3 };
console.log(decideCheckout([], stock));
console.log(decideCheckout([{ name: "tea", quantity: 0 }], stock));
console.log(decideCheckout([{ name: "tea", quantity: 3 }], stock));
console.log(decideCheckout([{ name: "rice", quantity: 2 }], stock));
const contractChecks = [
  decideCheckout([], stock) === "empty",
  decideCheckout([{ name: "tea", quantity: 1 }], stock) === "ready",
];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

Client validation does not reserve stock. The server must revalidate and reserve atomically when the order is committed.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>

- Guard clauses return on failure.
- Client validation does not reserve stock.
