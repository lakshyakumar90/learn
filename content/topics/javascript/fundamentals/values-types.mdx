## How it works

<CodeRunner title="Build: Values and types" expect="pence 250\ninvalid &quot;&quot;\ninvalid &quot;2x&quot;\ninvalid &quot;0&quot;\npence 375\nfallback preserves zero 0\ncontract true">
{`function parseQuantity(input) {
  if (typeof input !== "string" || input.trim() === "") return null;
  const quantity = Number(input);
  if (!Number.isInteger(quantity) || quantity < 1) return null;
  return quantity;
}
const priceInPence = 125;
const inputs = ["2", "", "2x", "0", "3"];
for (const input of inputs) {
  const quantity = parseQuantity(input);
  if (quantity === null) {
    console.log("invalid", JSON.stringify(input));
    continue;
  }
  const total = quantity * priceInPence;
  console.log("pence", total);
}
console.log("fallback preserves zero", 0 ?? 10);
const contractChecks = [parseQuantity("") === null, parseQuantity("2") === 2];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

## Why it works this way

Integer minor units avoid simple decimal errors. Currency precision and rounding still require a deliberate tested policy.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
