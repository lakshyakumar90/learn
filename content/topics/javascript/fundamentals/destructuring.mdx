<CodeRunner title="Build: Destructuring, spread, and rest" expect="tea\n10\nprice\ntrue\ntrue\ncontract true">
{`function makeSearchOptions(input = {}) {
  const { query = "", limit = 10, ...extra } = input;
  const safeQuery = typeof query === "string" ? query.trim() : "";
  const safeLimit = Number.isInteger(limit) && limit > 0 ? limit : 10;
  return { ...extra, query: safeQuery, limit: safeLimit };
}
const options = makeSearchOptions({
  query: "  tea  ",
  limit: 0,
  sort: "price",
});
const { query, limit, sort } = options;
console.log(query);
console.log(limit);
console.log(sort);
console.log(makeSearchOptions().query === "");
console.log(makeSearchOptions({ query: null }).query === "");
const contractChecks = [
  makeSearchOptions({ query: null }).query === "",
  options.limit === 10,
];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

Concise unpacking can conceal missing validation. Sanitize query and limit before handing them to the search implementation.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
