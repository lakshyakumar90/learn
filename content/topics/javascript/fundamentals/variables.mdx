<CodeRunner title="Build: Variables — var, let, const" expect="1\n2\ntea,rice\nlocked\ncontract true">
{`function makeOrder() {
  const order = { status: "draft", items: [] };
  function add(name) {
    if (order.status !== "draft") return "locked";
    order.items.push(name);
    return order.items.length;
  }
  function submit() {
    order.status = "submitted";
    return order.items.slice();
  }
  return { add, submit };
}
const order = makeOrder();
console.log(order.add("tea"));
console.log(order.add("rice"));
console.log(order.submit().join(","));
console.log(order.add("coffee"));
const contractChecks = [
  order.add("extra") === "locked",
  order.submit().length === 2,
];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

## Why it works this way

Let makes reassignment explicit. Shallow freezing cannot replace workflow rules such as refusing writes after submission.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>

## Mistakes that reach production

### Every callback reads the same loop binding

Run the reproduction, then the corrected version. Compare the value at the boundary; the fix changes the cause rather than hiding the symptom.

## Takeaways

- Check the value that crosses the boundary before choosing the syntax.
- Const prevents rebinding, not object mutation.
- Let makes reassignment explicit.
