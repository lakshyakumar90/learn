## How it works

<Diagram id="js-types" />

JSON restores plain data, not Date instances. Normalize names, reject invalid dates and choose an explicit UTC timestamp.

### Build the working version

<CodeRunner title="Build: Strings and template literals" expect="Meera\n1250\n2026-10-12">
{`function readOrder(payload) {
  const order = JSON.parse(payload);
  if (typeof order.name !== "string") throw new Error("missing name");
  const name = order.name.trim().normalize("NFC");
  const createdAt = new Date(order.createdAt);
  if (Number.isNaN(createdAt.getTime())) throw new Error("invalid date");
  return {
    name,
    totalPence: Math.round(order.total * 100),
    date: createdAt.toISOString().slice(0, 10),
  };
}
const payload = JSON.stringify({
  name: "  Meera  ",
  total: 12.5,
  createdAt: "2026-10-12T12:00:00Z",
});
const order = readOrder(payload);
console.log(order.name);
console.log(order.totalPence);
console.log(order.date);`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

String length counts UTF-16 code units, not visible characters. Use locale-aware formatting for display and machine-readable timestamps for storage.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>
