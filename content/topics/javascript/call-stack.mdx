Every call pushes a frame — its variables plus where to resume — and every
return pops it. Interviewers ask this because "Maximum call stack size
exceeded" and frozen pages both start here, and reading a trace starts here
too.

## Real-life situation

A receipt printer recurses into bundled items, but a bundle containing
itself loops forever and the tab dies with a stack overflow. The trace shows
the same function repeated — the giveaway. The fix is a visited set plus an
iterative fallback, but noticing the repeated frame is the interview skill.

## When depth matters

Recursion fits nested data (trees, comments, DOM walks). Flat sequences
want loops, and unbounded depth wants chunking so frames pop between
batches. Depth is always bounded — engines don't do tail-call optimization.

## Key takeaways

- Calls push frames; returns pop them; last in, first out.
- Overflow means calls outrun returns — find the missing base case.
- Read traces top-down: the thrower first, your code a few frames down.
