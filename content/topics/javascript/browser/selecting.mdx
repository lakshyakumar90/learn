### Build the working version

<CodeRunner title="Build: Selecting and changing elements" expect="2\nmissing\n2\nmatch count 2\ncontract true">
{`const rows = [
  { id: "tea", quantity: 1 },
  { id: "rice", quantity: 2 },
  { id: "coffee", quantity: 0 },
];
function selectById(id) {
  return rows.find((row) => row.id === id) ?? null;
}
function increment(id) {
  const row = selectById(id);
  if (!row) return "missing";
  row.quantity++;
  return row.quantity;
}
console.log(increment("tea"));
console.log(increment("unknown"));
console.log(selectById("rice").quantity);
console.log("match count", rows.filter((row) => row.quantity > 0).length);
const contractChecks = [
  selectById("unknown") === null,
  selectById("tea").quantity === 2,
];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

## Why it works this way

Cache stable containers, not disappearing children. Escape externally constructed identifiers and avoid interpolating arbitrary selector fragments.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>

## Takeaways

- Check the value that crosses the boundary before choosing the syntax.
- QuerySelector returns the first match or null.
- Cache stable containers, not disappearing children.
