### Build the working version

<CodeRunner title="Build: Rendering, reflow, and performance" expect="batched updates 1\nmicrotask completion does not prove pixels painted\ncontract true">
{`function scheduleRender(render) {
  let queued = false;
  return () => {
    if (queued) return;
    queued = true;
    queueMicrotask(() => {
      queued = false;
      render();
    });
  };
}
let paintsRequested = 0;
const update = scheduleRender(() => paintsRequested++);
update();
update();
update();
await Promise.resolve();
console.log("batched updates", paintsRequested);
console.log("microtask completion does not prove pixels painted");
const contractChecks = [paintsRequested === 1, typeof update === "function"];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

RequestAnimationFrame aligns visual updates but cannot make heavy callbacks cheap. Group measurements and mutations to avoid forced-layout loops.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>

## Takeaways

- Check the value that crosses the boundary before choosing the syntax.
- DOM changes precede style, layout and paint.
- RequestAnimationFrame aligns visual updates but cannot make heavy callbacks cheap.
