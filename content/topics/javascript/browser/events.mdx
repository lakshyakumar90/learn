### Build the working version

<CodeRunner title="Build: Events — capture, bubble, delegation" expect="completed\nreopened\nignored\nrecords 10000\ncompleted 0\ncontract true">
{`const todos = Array.from({ length: 10000 }, (_, id) => ({
  id,
  done: false,
}));
const byId = new Map(todos.map((todo) => [todo.id, todo]));
function handleAction(id, action) {
  const todo = byId.get(Number(id));
  if (!todo || action !== "toggle") return "ignored";
  todo.done = !todo.done;
  return todo.done ? "completed" : "reopened";
}
console.log(handleAction("42", "toggle"));
console.log(handleAction("42", "toggle"));
console.log(handleAction("missing", "toggle"));
console.log("records", todos.length);
console.log("completed", todos.filter((todo) => todo.done).length);
const contractChecks = [todos.length === 10000, byId.get(42).done === false];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

<CodeRunner env="dom" title="Delegate 10,000 to-do actions" expectDom="Rows: 10000" html={`<p id="status">Preparing</p>

const fragment = document.createDocumentFragment();
for (let id = 0; id < 10000; id++) {
  const row = document.createElement("li");
  const button = document.createElement("button");

list.append(fragment);
list.addEventListener("click", (event) => {
  const button = event.target.closest("button[data-id]");
  if (!button || !list.contains(button)) return;
  button.textContent = "Done " + button.dataset.id;
  document.querySelector("#status").textContent =
    "Completed " + button.dataset.id;
});
document.querySelector("#status").textContent = "Rows: " + list.children.length;
console.log("one delegated listener");`}
</CodeRunner>

## Why it works this way

Delegation covers added children naturally. Some events do not bubble, and stopPropagation can prevent the parent from receiving them.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>

## Takeaways

- Check the value that crosses the boundary before choosing the syntax.
- Bubbling visits ancestors after the target.
- Delegation covers added children naturally.
