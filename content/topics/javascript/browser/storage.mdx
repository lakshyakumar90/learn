### Build the working version

<CodeRunner title="Build: Browser storage" expect="Meera\nfallback true">
{`const storage = new Map();
function saveDraft(draft) {
  const envelope = { version: 1, draft };
  storage.set("checkout", JSON.stringify(envelope));
}
function readDraft() {
  try {
    const value = JSON.parse(storage.get("checkout") ?? "null");
    if (value?.version !== 1 || typeof value.draft?.name !== "string") {
      return { name: "" };
    }
    return value.draft;
  } catch {
    return { name: "" };
  }
}
saveDraft({ name: "Meera" });
console.log(readDraft().name);
storage.set("checkout", "broken");
console.log("fallback", readDraft().name === "");`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

The console sample uses Map for determinism. Catch real browser reads and writes, keep secrets out and prefer IndexedDB for large data.

Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
