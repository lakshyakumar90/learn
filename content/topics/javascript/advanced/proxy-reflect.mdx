## How it works

### Build the working version

<CodeRunner title="Build: Proxy and Reflect" expect="quantity 3\nquantity must be positive\nunchanged 3\nseparate identity true\ncontract true">
{`const cart = { quantity: 1 };
const validated = new Proxy(cart, {
  set(target, key, value, receiver) {
    if (key === "quantity" && (!Number.isInteger(value) || value < 1)) {
      throw new RangeError("quantity must be positive");
    }
    return Reflect.set(target, key, value, receiver);
  },
});
validated.quantity = 3;
console.log("quantity", validated.quantity);
try {
  validated.quantity = -1;
} catch (error) {
  console.log(error.message);
}
console.log("unchanged", cart.quantity);
console.log("separate identity", validated !== cart);
const contractChecks = [cart.quantity === 3, validated !== cart];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

A proxy has different identity and language invariants. Validation is not a security boundary if the raw target remains publicly writable.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>

## Mistakes that reach production

### A shallow copy shares nested data

Run the reproduction, then the corrected version. Compare the value at the boundary; the fix changes the cause rather than hiding the symptom.

<CodeRunner title="Bug: A shallow copy shares nested data" expect="Delhi">

console.log(account.address.city);`}
</CodeRunner>

### Inherited names pass a naive membership test
