Array methods encode intent: `map` transforms, `filter` selects, `reduce`
folds. Interviewers ask this to hear you pick by return shape — and to catch
the in-place `sort` corrupting shared state.

## Real-life situation

A dashboard lists orders over $50 with their revenue total. `filter` picks
the big orders, `map` pulls their totals, `reduce` folds one revenue number
— three readable steps, no manual loop, original array untouched. Then a
`sort` for the leaderboard mutates the shared ranks array, and every other
widget shows the new order too.

{`const orders = [
  { id: 1, total: 30 },
  { id: 2, total: 120 },
  { id: 3, total: 80 },
];
const big = orders.filter(function (o) {
  return o.total >= 50;
});
console.log(big.length);
const sums = big.map(function (o) {
  return o.total;
});
console.log(sums[0]);
console.log(sums[1]);
const revenue = sums.reduce(function (sum, n) {
  return sum + n;
}, 0);
console.log(revenue);
const ranks = [10, 9, 80];
console.log(ranks.sort()[0]);
console.log(
  ranks.slice().sort(function (a, b) {
    return a - b;
  })[0],
);`}

Try changing the filter to `o.total > 100` and predict the revenue first.
Then sort a copy with `toSorted` and compare. Time yourself rewriting the
pipeline with a single `reduce`, then compare readability honestly.

## Mutating versus new

Chain the non-mutating ones (`map`, `filter`, `slice`, `toSorted`) for
shared data. Reserve `sort`, `splice` and `reverse` for local scratch arrays
nobody else sees.

## Key takeaways

- `map`/`filter` return new arrays; `reduce` folds to one value.
- Default `sort` is lexicographic and in place — pass a comparator, copy first.
- Pick methods by return shape: transform, select, find or fold.
