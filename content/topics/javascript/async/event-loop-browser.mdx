## How it works

<ScenarioPlayer scenario="event-loop-long-task" />

A task keeps the main thread until it returns. Microtasks drain before another task can start; chunking creates rendering opportunities without guaranteeing a paint after each batch.

### Build the working version

<CodeRunner title="Build: The event loop in the browser" expect="spinner can update between batches\nrows 10000\ntotal 49995000\nbatches 20\ncontract true">
{`const rows = Array.from({ length: 10000 }, (_, index) => index);
async function processRows(rows, size) {
  let total = 0;
  let batches = 0;
  for (let start = 0; start < rows.length; start += size) {
    const batch = rows.slice(start, start + size);
    for (const row of batch) total += row;
    batches++;
    await sleep(0);
  }
  return { total, batches };
}
console.log("spinner can update between batches");
const result = await processRows(rows, 500);
console.log("rows", rows.length);
console.log("total", result.total);
console.log("batches", result.batches);
const contractChecks = [result.total === 49995000, result.batches === 20];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

function process(rows) {
  let total = 0;
  for (const row of rows) {
    for (let pass = 0; pass < 3000; pass++) total += Math.sqrt(row + pass);
  }
  return Math.round(total);
}
document.querySelector("#block").onclick = () => {
  status.textContent = "Working…";
  const result = process(rows);
  status.textContent = "Blocked: " + result;
};
document.querySelector("#chunk").onclick = async () => {
  let total = 0;
  for (let start = 0; start < rows.length; start += 100) {
    total += process(rows.slice(start, start + 100));
    status.textContent = "Processed " + Math.min(start + 100, rows.length);
    await sleep(0);
  }
  status.textContent = "Chunked: " + total;
};
document.querySelector("#worker").onclick = () => {
  const source =
    process.toString() + ";onmessage = e => postMessage(process(e.data));";
  const url = URL.createObjectURL(
    new Blob([source], { type: "text/javascript" }),
  );
  const worker = new Worker(url);
  worker.onmessage = (event) => {
    status.textContent = "Worker: " + event.data;
    worker.terminate();
    URL.revokeObjectURL(url);
  };
  worker.postMessage(rows);
  status.textContent = "Worker started";
};`}
</CodeRunner>

## Why it works this way

Workers separate CPU work but add startup and message costs. Use short batches for moderate work and workers for sustained computation.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>



<WhenToUse use="large work must leave other callbacks time" avoid="coordination costs exceed tiny calculations" alternative="a worker for sustained CPU work" />

## Takeaways

- Check the value that crosses the boundary before choosing the syntax.
- A task keeps the main thread until it returns.
- Workers separate CPU work but add startup and message costs.
