## How it works

<Diagram id="js-promise-states" />

AllSettled returns a status record for every input. All requires every success, race settles first and any finds the first fulfillment.

### Find its limit

A rejected request has no useful fallback. Change the input and predict the output before you run it. The failure comes from a specific default, lifetime or ownership assumption; keep that assumption visible in the test.

### Build the working version

<CodeRunner title="Build: Promise combinators" expect="profile ready\nfallback weather unavailable\nposts ready\nwidgets 3\ncontract true">
{`async function loadWidget(name, fails) {
  await sleep(5);
  if (fails) throw new Error(name + " unavailable");
  return { name, ready: true };
}
const results = await Promise.allSettled([
  loadWidget("profile", false),
  loadWidget("weather", true),
  loadWidget("posts", false),
]);
for (const result of results) {
  if (result.status === "fulfilled") console.log(result.value.name, "ready");
  else console.log("fallback", result.reason.message);
}
console.log("widgets", results.length);
const contractChecks = [
  results.filter((item) => item.status === "fulfilled").length === 2,
  results.length === 3,
];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

Coordination does not cancel work. Use AbortSignal for deadlines and bound concurrency before starting thousands of requests.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
