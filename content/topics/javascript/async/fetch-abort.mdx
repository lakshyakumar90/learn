### Find its limit

### Build the working version

<CodeRunner title="Build: Fetch and AbortController" expect="ready\ncancelled\ncontract true">
{`async function loadUsers(timeout) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), timeout);
  try {
    const response = await fakeFetch("/users", {
      latencyMs: 10,
      signal: controller.signal,
    });
    if (!response.ok) throw new Error("HTTP " + response.status);
    return { state: "ready", count: (await response.json()).length };
  } catch (error) {
    return { state: error.name === "AbortError" ? "cancelled" : "failed" };
  } finally {
    clearTimeout(timer);
  }
}
console.log((await loadUsers(100)).state);
console.log((await loadUsers(1)).state);
const contractChecks = [
  (await loadUsers(100)).count === 3,
  (await loadUsers(1)).state === "cancelled",
];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

Abort is not a server rollback. A request ID still protects UI updates when cancellation races with completion.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>
