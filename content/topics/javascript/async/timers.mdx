## How it works

<Diagram id="js-runtime" />

Timeout delay is a scheduling minimum, not an appointment. Other tasks and background policies can delay execution.

### Build the working version

<CodeRunner title="Build: Timers and scheduling" expect="start 3000\nlater 1800\nexpired 0\ntimer fired true\ncontract true">
{`function makeExpiry(now, lifetime) {
  const deadline = now() + lifetime;
  return () => Math.max(0, deadline - now());
}
let current = 1000;
const remaining = makeExpiry(() => current, 3000);
console.log("start", remaining());
current += 1200;
console.log("later", remaining());
current += 2500;
console.log("expired", remaining());
let ticks = 0;
const interval = setInterval(() => ticks++, 5);
await sleep(18);
clearInterval(interval);
console.log("timer fired", ticks > 0);
const contractChecks = [remaining() === 0, ticks > 0];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

Inject a clock to test deadline arithmetic. Browser animation uses requestAnimationFrame; Node timer handles additionally support unref.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.

## Takeaways

- Check the value that crosses the boundary before choosing the syntax.
- Timeout delay is a scheduling minimum, not an appointment.
- Inject a clock to test deadline arithmetic.
