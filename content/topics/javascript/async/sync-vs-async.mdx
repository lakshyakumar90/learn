## How it works

<Diagram id="js-runtime" />

Async returns a promise but starts synchronously. Promise.resolve around a calculation does not move that calculation to another thread.

Follow the highlighted step or expand the diagram to inspect the boundary. The visual describes execution or data ownership; timing and memory totals are not inferred from its animation.

### Build the working version

<CodeRunner title="Build: Synchronous vs asynchronous" expect="saving 12\nUI can continue\nsaved\ntotal 12\nsame calculation 12\ncontract true">
{`function priceCart(items) {
  return items.reduce((total, item) => total + item.price, 0);
}
async function saveCart(items) {
  console.log("saving", priceCart(items));
  await sleep(5);
  return "saved";
}
const cart = [{ price: 4 }, { price: 8 }];
const pending = saveCart(cart);
console.log("UI can continue");
const status = await pending;
console.log(status);
console.log("total", priceCart(cart));
const totalPromise = Promise.resolve(priceCart(cart));
console.log("same calculation", await totalPromise);
const contractChecks = [status === "saved", priceCart(cart) === 12];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

Overlap waiting with promises; separate CPU work with a worker. A task yield helps moderate work share time.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>

## Takeaways

- Check the value that crosses the boundary before choosing the syntax.
- Async returns a promise but starts synchronously.
- Overlap waiting with promises; separate CPU work with a worker.
