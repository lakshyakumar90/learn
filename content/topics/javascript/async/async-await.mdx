{`async function loadJson(url, attempts = 3) {
  for (let attempt = 1; attempt <= attempts; attempt++) {
    const controller = new AbortController();
    const timer = setTimeout(() => controller.abort(), 100);
    try {
      const response = await fakeFetch(url, {
        latencyMs: 5,
        signal: controller.signal,
      });
      if (!response.ok) throw new Error("HTTP " + response.status);
      return await response.json();
    } catch (error) {
      if (attempt === attempts) throw error;
      await sleep(5 * attempt);
    } finally {
      clearTimeout(timer);
    }
  }
}
const [users, posts] = await Promise.all([
  loadJson("/users"),
  loadJson("/posts"),
]);
console.log(users[0].name);
console.log("posts", posts.length);`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

This client retries reads only. Real clients need retryable status rules, server Retry-After hints and idempotency protection for writes.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>
