{`function loadJson(url) {
  return fakeFetch(url, { latencyMs: 5 }).then((response) => {
    if (!response.ok) throw new Error("HTTP " + response.status);
    return response.json();
  });
}
const profileRequest = loadJson("/users");
const postsRequest = loadJson("/posts");
console.log("requests started");
await Promise.all([profileRequest, postsRequest])
  .then(([users, posts]) => {
    const profile = users.find((user) => user.id === 1);
    const feed = posts.filter((post) => post.userId === profile.id);
    console.log("profile", profile.name);
    console.log("posts", feed.length);
  })
  .catch((error) => {
    console.log("dashboard unavailable", error.message);
  });
const contractChecks = [
  typeof profileRequest.then === "function",
  typeof postsRequest.then === "function",
];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

Parallel loading removes unnecessary waits. All does not cancel other requests, and allSettled is better when partial widgets remain useful.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>
