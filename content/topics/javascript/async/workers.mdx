## How it works

### Build the working version

<CodeRunner title="Build: Concurrency and Web Workers" expect="rows 10000\nfood 10000\ntravel 10000\npure computation can move into a worker\ncontract true">
{`function calculateReport(rows) {
  const groups = new Map();
  for (const row of rows) {
    const previous = groups.get(row.category) ?? 0;
    groups.set(row.category, previous + row.amount);
  }
  return Array.from(groups.entries());
}
const rows = Array.from({ length: 10000 }, (_, index) => ({
  category: index % 2 === 0 ? "food" : "travel",
  amount: 2,
}));
const report = calculateReport(rows);
console.log("rows", rows.length);
console.log("food", report.find(([key]) => key === "food")[1]);
console.log("travel", report.find(([key]) => key === "travel")[1]);
console.log("pure computation can move into a worker");
const contractChecks = [
  report.length === 2,
  report.every(([, total]) => total === 10000),
];
if (!contractChecks.every(Boolean)) {
  throw new Error("The boundary contract was broken");
}
console.log("contract", contractChecks.every(Boolean));`}
</CodeRunner>

The console runner is an isolated browser worker. These core examples are also checked in Node; DOM behavior belongs to the browser frame, and fakeFetch is sample data rather than a real network request.

## Why it works this way

Startup and data copying can dominate small calculations. Transfer suitable buffers, handle errors and terminate unused workers.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.
</ConceptCard>
