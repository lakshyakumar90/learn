## Why it works this way

Choose ownership and default policy first. Test zero, blank, missing and repeated inputs instead of relying on happy paths.

<ConceptCard variant="under-hood">
Keep the operation's contract separate from its implementation. A faster path is useful only when it preserves the same outputs, error behavior and ownership rules; validate those boundaries before relying on a host-specific optimization.

## Mistakes that reach production

### Falsy defaults replace a valid zero

Run the reproduction, then the corrected version. Compare the value at the boundary; the fix changes the cause rather than hiding the symptom.

<CodeRunner title="Fix: Falsy defaults replace a valid zero" expect="0">
{`const price = 0;

### Blank input becomes zero

Run the reproduction, then the corrected version. Compare the value at the boundary; the fix changes the cause rather than hiding the symptom.

<CodeRunner title="Bug: Blank input becomes zero" expect="true">
{`const input = "";

</CodeRunner>

<CodeRunner title="Fix: Blank input becomes zero" expect="false">
{`const input = "";
const accepted = input.trim() !== "" && Number.isInteger(Number(input));
