`async`/`await` writes asynchronous code that reads top-to-bottom: awaits
for sequencing, `try`/`catch` for errors. Interviewers ask this because the
syntax looks synchronous while the pitfalls (serial loops, uncaught
rejections, fire-and-forget) are anything but.

## Real-life situation

A settings save retries a flaky endpoint with backoff: try, wait a little
longer each time, give up after three attempts with a real error. Written
with `await`, the retry loop reads like its flowchart. Written with nested
callbacks, the same logic hides behind three indent levels.

## When await helps, when it hurts

Await for sequencing and error handling. Never await independent calls one
by one — launch them all, gather once. And never fire-and-forget an async
call in reviewed code: return it or catch it.

## Key takeaways

- `async` wraps returns in promises; `await` parks only its function.
- Rejected awaits throw at that line — guard with `try`/`catch`.
- Launch independent work together; gather with `all` or `allSettled`.
