`var`, `let` and `const` all declare variables, but they differ in where
the variable is visible and what happens before its line runs.
Interviewers ask this because scope bugs — a loop counter leaking, a
variable read too early — are silent and everywhere.

## Real-life situation

A checkout page applies a member discount inside an `if` block. With `var`,
the discount variable leaks out and a later line reuses its stale value for
guests. With `let` and `const`, each variable stays inside its block and the
bug cannot happen. The runner below shows both behaviors side by side.

## When to use which

Default to `const`. Use `let` when reassignment is the point (counters,
accumulators). There is no modern reason to write `var` — treat it as
read-only legacy you will still meet in old codebases.

## Key takeaways

- `var` is function-scoped and reads as `undefined` before its line.
- `let` and `const` are block-scoped and throw before their line (temporal dead zone).
- Hoisting moves declarations, never assignments.
