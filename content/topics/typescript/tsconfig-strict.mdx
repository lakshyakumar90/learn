`tsconfig.json` is where a project sets its standards: how strict the
checker is, what language level to emit, and which built-in libraries
exist. Interviewers ask "what does strict actually enable?" — `strict:
true` is one switch arming a family of flags.

## Real-life situation

A legacy project turns `strict` on and fifty errors appear overnight.
Almost all are real: an `undefined` passed as a name, a variable read
before assignment, a `null` nobody admitted. Each flag below catches one
species — `strictNullChecks` (no silent `undefined`), `noImplicitAny`
(no silent `any`), `strictPropertyInitialization` and friends. Turning
them on file by file beats turning them off forever.

chooses the emitted language level (this topic uses ES2022) while `lib`
chooses which built-ins exist (`DOM` for browsers). Our sandbox pins
both, and every runner labels its mode.

## Key takeaways

- `strict: true` arms the flag family — null checks and no silent `any` first.
- `target` is emit level, `lib` is available built-ins; they are independent.
- Legacy code: enable flags incrementally, never surrender globally.
