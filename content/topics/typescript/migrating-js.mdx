Nobody rewrites a working app in a weekend. Migration is a ratchet:
check the JavaScript you have, annotate the seams, rename files one by
one, and tighten strictness last. Interviewers ask for the order — recite
these five steps.

## Real-life situation

A checkout helper has grown for two years with no types. Step one flips
on `checkJs` so the compiler reads the existing JavaScript. Step two adds
JSDoc annotations to the trickiest function. Steps three and four rename
one file to `.ts` and fix only its errors. Step five raises strictness.
Each step ships; the build never goes red for a week.

Try narrowing the `catch` variable — `e instanceof Error ? e.message :
"unknown"` — and the Types tab goes clean. That is step four in
miniature: one file, one error species, fixed and shipped. `allowJs`
lets `.js` files stay in the build during the transition, `checkJs`
types them loosely, and JSDoc (`@param {number[]} prices`) annotates
without renaming anything.

## Key takeaways

- Check first (`checkJs`), annotate second (JSDoc), rename third, strict last.
- Fix one error species at a time; every step must ship green.
- `allowJs` keeps old files building while new files get full checking.
