Chat has two doors that stay in sync: socket events for live exchange and
REST for history and sending from cold state. Every message is stored with
a delivery state — sent when the peer is offline, delivered when present,
read when the thread opens. Typing and presence are ephemeral broadcasts;
only chat content is durable. The Redis adapter lets any instance reach any
user room, so the design survives more than one server.
